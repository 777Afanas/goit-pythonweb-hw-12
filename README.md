# goit-pythonweb-hw-12

# REST API Contacts Application — Фінальний проєкт (GoIT Python Web)

REST API застосунок для управління контактами, розроблений на базі FastAPI, SQLAlchemy, PostgreSQL, Redis та Docker Compose. Проєкт покритий модульними та інтеграційними тестами з контролем покриття понад 75%, задокументований за допомогою Sphinx і містить механізми рольового доступу та кешування.

---

## Реалізований функціонал та виконання вимог ТЗ

### 1. Документація коду (Sphinx)

- Всі ключові модулі, роути, репозиторії та сервісні класи містять детальні `docstrings`.
- Конфігурація та вихідні файли документації зібрані у директорії `docs/` (`docs/source/conf.py`, `index.rst`).

### 2. Модульне та інтеграційне тестування (> 75% покриття)

- **Модульні тести (`tests/test_repository/`)**: перевіряють методи репозиторіїв `UserRepository` та `ContactRepository` в ізоляції від реальної БД за допомогою мокування сесії (`mock_session`).
- **Інтеграційні тести (`tests/test_api/`)**: перевіряють усі ендпоінти роутів (`/api/auth`, `/api/contacts`, `/api/users`), обробку HTTP-запитів, схеми валідації Pydantic, хешування паролів та доступ за ролями на тестовій базі даних SQLite в пам'яті.
- **pytest-cov**: загальне сумарне покриття становить **92%** (при вимозі > 75%). Усі 46 тестів проходять успішно.

### 3. Кешування за допомогою Redis

- Реалізовано кешування користувача у функції `get_current_user` (`src/services/auth.py`). При повторних запитах із валідним JWT дані зчитуються з Redis, мінімізуючи запити до основної бази даних.

### 4. Механізм скидання пароля

- Реалізовано ендпоінти запиту на скидання пароля та підтвердження зміни нового пароля за допомогою окремого підписаного токена безпеки.
- Відправка посилань для відновлення налаштована через поштовий сервіс FastAPI-Mail (у тестовому середовищі виклики мокуються).

### 5. Ролі користувачів та контроль доступу

- Реалізовано перелік ролей `UserRole`: `user` та `admin`.
- Встановлено перевірку залежностей: оновлення стандартного аватара користувача дозволено виконувати лише адміністраторам (`admin`).

### 6. Додаткове завдання: пара токенів (Access & Refresh)

- Реалізовано повноцінний JWT-механізм з використанням короткоживучого `access_token` для авторизації та збереженням валідного `refresh_token` у базі даних для його поновлення.

### 7. Контейнеризація та безпека

- Усі сервіси (застосунок, PostgreSQL, Redis) запускаються єдиною командою через `docker-compose.yaml`.
- Конфіденційні дані не зберігаються у кодовій базі: використовується `.env` (шаблон зі структурою змінних надано у `.env.example`).

## Встановлення та запуск

### 1. Налаштування змінних оточення

Створіть локальний файл `.env` на основі наданого шаблону:

```bash
cp .env.example .env
```

Для запуску через Docker переконайтеся, що хости сервісів вказують на назви відповідних контейнерів (`DATABASE_URL` з хостом `db`, `REDIS_HOST=redis_cache`).

### 2. Запуск сервісів у Docker

```bash
docker compose up -d --build
```

- **Swagger UI (інтерактивна документація):** [http://localhost:8000/docs](http://localhost:8000/docs)
- **ReDoc:** [http://localhost:8000/redoc](http://localhost:8000/redoc)

Зупинка сервісів:

```bash
docker compose down
```

### Запуск усередині Docker-контейнера:

```bash
docker compose exec app poetry run pytest
```

```bash

poetry run pytest tests/test_repository/ -v

# Запуск усіх тестів із виведенням звіту покриття коду:
poetry run pytest --cov=src --cov-report=term-missing
```
